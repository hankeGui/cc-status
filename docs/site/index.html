cc-status

A multi-line, mode-switchable status line for Claude Code.

Rust npm: @cc-status-line/cli macOS · Linux MIT
GitHub README 中文文档

What it looks like

Mode detailed — three lines, all metrics:

~/hanke-dev/cc-status main Claude Opus 4.7
ctx 86% █████▏ 154.6k/950k ↑12.3k ↓2.1k +865 🎯89% cache 4:42 hit 96% 🔥 32.4k/min
skills: jira×3 wiki×1 mcp: github×2

Mode cost — focused on USD spend:

~/hanke-dev/cc-status main Opus ctx 85% █████▏ 154.6k/950k
last $0.012 sess $1.42 today $4.18 7d $24.50

7 built-in modes · build your own with ccs mode add / ccs mode append / ccs mode edit.

Why

Most Claude Code status lines stop at "model name + remaining percent." That hides what actually drives cost and behavior. cc-status surfaces it:

Token flow

Last turn input / output / cache write, with hit rate. See cache wins as they happen.

Prompt-cache TTL

5-minute countdown; warns red under 1 minute. Don't pay the rebuild cost by accident.

USD cost

Per-turn / per-session / today / last-7-days. Built-in Anthropic prices, override per model.

Real context capacity

Backsolves the 1M-tier window so the bar means something on extended-context models.

Skill / MCP usage

Counts which Skills and MCP servers got called this session — handy when debugging your prompt.

Worktree-aware git

Branch, ahead/behind, dirty flags, and the worktree name when you're inside one.

Custom plugin segments

Drop an executable, reference it as {plugin:NAME}. Built-in scaffolder, debug-runner, and health-checker — your script ships in three commands.

Drag-and-drop mode editor

ccs config edit opens a visual editor in your browser. Drag segments between modes and the palette, click Save. Pure stdlib, no daemon — server exits 5s after save.

Conversational helper

Just say "switch to detailed" or "build me a plugin that shows X" inside Claude Code. The skill teaches Claude how to drive cc-status, no docs needed.

Install

npm (recommended for Claude Code users)

npm install -g @cc-status-line/cli
ccs setup

curl

curl -fsSL https://raw.githubusercontent.com/hankeGui/cc-status/main/install.sh | sh
ccs setup

From source

cargo install --git https://github.com/hankeGui/cc-status --locked

After install, ccs setup writes the statusLine block into ~/.claude/settings.json with a backup. Restart Claude Code and you're done.

Power user moves

ccs explain                         # legend for every glyph
ccs status                          # full session dashboard
ccs cost --days 30                  # ASCII cost-by-day chart
ccs mode append cost_today          # add a segment to your current mode
ccs mode edit                       # open the current mode in $EDITOR
ccs config edit                     # drag-and-drop mode editor in the browser
ccs daemon start                    # optional Unix-socket daemon
ccs upgrade                         # auto-detect install method and update

Custom segments in 30 seconds

Need a metric cc-status doesn't ship? ccs plugin scaffolds, debug-runs, and health-checks executable plugins under <config>/plugins/.

ccs plugin new hello                # scaffold a sh template (or --lang python)
ccs plugin run hello                # debug: stdout / stderr / exit / timing
ccs mode append plugin:hello        # wire it into your status line
ccs plugin doctor                   # health-check every plugin you own

Templates ship with the contract embedded as comments — stdin schema, 250 ms timeout, 80-char output cap, ANSI SGR allowed. ccs plugin run shows the exact value the status line will display, so you never have to restart Claude Code to verify.
